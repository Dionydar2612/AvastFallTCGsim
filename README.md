# AvastFall Playtest (เว็บทดลองเล่น)

หน้าเว็บเป็นสแตติก ไม่ต้อง build ส่วน `server.js` (Node ล้วน ไม่ต้อง npm install) เสิร์ฟหน้าเว็บและเก็บข้อเสนอแนะ รันในเครื่อง: `ADMIN_KEY=รหัส node server.js` แล้วเปิด http://localhost:8080

## โครงสร้างไฟล์ (แยกตามหน้าที่)

```
index.html                 โครงหน้า + ลำดับโหลดสคริปต์
css/style.css              สไตล์ทั้งหมด
assets/card-back.jpg       ลายหลังการ์ด (รูปหน้าการ์ดดึงจาก card-api ทั้งหมด)

js/engine/engine.js        กติกาเกม (ไม่แตะ DOM) · กติกาคงที่: Domain 3 ใบ, เด็ค 60 ใบ, ธีอัลฟีตามข้อความ
js/effects/_kit.js         ตัวช่วยที่สคริปต์การ์ดใช้ร่วมกัน
js/effects/sd01..sd04.js   เอฟเฟกต์การ์ดแยกตามชุด  FX['SD04-012'] = {...}  + NOTES['SD04-012'] = '...'
js/bot.js                  บอท
server.js                  เซิร์ฟเวอร์เล็ก: เสิร์ฟหน้าเว็บ + ข้อเสนอแนะ (/api/feedback, /recommece)

js/data/cards-api.js       ชั้นดึงข้อมูล: card-api, สำเนาในเบราว์เซอร์, URL รูปการ์ด, ตรวจการ์ดใหม่/ข้อความเปลี่ยน
js/data/feedback-api.js    ส่งข้อเสนอแนะไปเซิร์ฟเวอร์
js/data/snapshot.js        ชุดการ์ดสำรอง และเป็น "ข้อความที่สคริปต์เขียนไว้ตามนั้น"

js/ui/*.js                 หน้าจอ (base, notes, data-sync, decks, render, setup, mydecks, game, modals, events, main)
```

UI ไม่รู้เรื่องการดึงข้อมูล (อ่านผ่าน `AF.cardData` เท่านั้น) และสคริปต์เอฟเฟกต์ไม่รู้เรื่อง UI แก้ส่วนหนึ่งไม่ต้องแตะอีกส่วน

## แก้/เพิ่มเอฟเฟกต์การ์ด
1. เปิดหน้าเว็บ → ชิป "ข้อมูลการ์ด" ด้านบน จะแสดงรายการ "ยังไม่มีสคริปต์" และ "ข้อความต่างจากที่สคริปต์เขียนไว้" (กด "ดูส่วนที่ต่าง" จะเห็นข้อความเดิมเทียบข้อความใน card-api)
2. แก้ `FX[รหัสการ์ด]` ในไฟล์ชุดนั้นใน `js/effects/` และถ้าตีความข้อความไม่ตรงตัวให้เขียน `NOTES[รหัสการ์ด]` ไว้ข้างกัน (แสดงในปุ่ม "ข้อสังเกต")
3. แก้รายการการ์ดนั้นใน `js/data/snapshot.js` ให้เหมือนข้อความล่าสุดใน card-api ป้าย "ข้อความเปลี่ยน" จะหาย

## เชื่อมกับ card-api
- ค่าเริ่มต้น https://avastfalltcglist.onrender.com (แก้ได้ที่ชิป "ข้อมูลการ์ด" หรือเปิดด้วย `?api=https://...`)
- ดึง `/api/cards` `/api/decks` `/api/elements` ทุกครั้งที่เปิดหน้า และเมื่อกลับมาที่แท็บหลังผ่านไปเกิน 90 วินาที เก็บสำเนาไว้ในเบราว์เซอร์ ถ้าต่อ API ไม่ได้จะใช้สำเนา หรือชุดสำรองใน `snapshot.js`
- **รูปการ์ดดึงจาก API** (`/images/<รหัส>.jpg?v=...` ตามฟิลด์ `image`) ไม่ได้ฝังในโค้ด ถ้ารูปโหลดไม่ได้จะเห็นลายหลังการ์ดแทน
- Render แพ็กเกจฟรีจะหลับเมื่อไม่มีคนใช้ การโหลดครั้งแรกอาจรอ ~30–60 วินาที

## หน้าตั้งค่า
เหลือเฉพาะ "โหมด" และ "ใครเล่นก่อน" ส่วนอื่นเป็นกติกาคงที่: Domain ต่อฝั่ง 3 ใบ · ธีอัลฟีตามข้อความการ์ด · เด็คต้อง 60 ใบเสมอ

## ข้อเสนอแนะจากผู้เล่น
- ปุ่ม "ข้อเสนอแนะ" (ต่อจาก "Update Note") ส่งไป `POST /api/feedback` เก็บใน `DATA_DIR/feedback.json`
- เจ้าของอ่านที่ **`/recommece?key=<ADMIN_KEY>`** (ใช้ `/recommend` ได้เหมือนกัน) กรองตามหัวข้อ ลบ และดาวน์โหลด JSON ได้ ถ้าไม่ตั้ง ADMIN_KEY ทุกคนที่รู้ลิงก์เปิดอ่านได้ แต่ลบไม่ได้
- กันสแปม: 5 ข้อความ / 10 นาที ต่อ IP, ช่องซ่อนดักบอท, จำกัดความยาว
- **บน Render:** ต้องเป็น Web Service (ดู `render.yaml`) ข้อมูลอยู่ในดิสก์ของเครื่อง แพ็กเกจฟรีไม่มีดิสก์ถาวร ข้อเสนอแนะจะหายเมื่อ deploy ใหม่หรือเครื่องรีสตาร์ต ถ้าต้องการให้อยู่ถาวรให้ผูก Persistent Disk (เสียเงิน) แล้วตั้ง `DATA_DIR` ไปที่ path ของดิสก์ หรือโหลด JSON เก็บไว้เป็นระยะ

## Update Note
ปุ่ม "Update Note" (เดิมชื่อ "ข้อสังเกต") แสดงบันทึกการอัปเดตจาก `UPDATE_NOTES` ใน `js/ui/notes.js` (เพิ่มรายการใหม่ไว้บนสุด) (เฉพาะสิ่งที่เพิ่ม/แก้ไข ไม่รวมข้อสังเกตการตีความการ์ด)

## เล่นออนไลน์กับเพื่อน (ห้องส่วนตัว)
โหมด "เล่นออนไลน์กับเพื่อน" ในหน้าตั้งค่า: สร้างห้อง → ส่งรหัส 5 ตัวหรือลิงก์ `?room=รหัส` ให้เพื่อน → ทั้งคู่เลือกเด็คแล้วกด "พร้อม"
- แบบ lockstep: ทั้งสองเบราว์เซอร์รัน engine เดียวกันด้วย seed เดียวกัน `server.js` ส่งต่อแค่ "ตัวเลือกที่ผู้เล่นกด" (SSE `GET /api/room/events` + `POST /api/room/send|create|join`) ไม่รู้กติกาเกม ไม่ต้องติดตั้ง package เพิ่ม · โค้ดฝั่งหน้าเว็บอยู่ที่ `js/ui/online.js`
- ห้องเก็บในหน่วยความจำ (รีสตาร์ต/deploy ใหม่แล้วหาย, ห้องว่างเกิน 15 นาที/ค้างเกิน 3 ชม. ถูกลบ) รีเฟรชหน้าระหว่างเกมแล้วเล่นต่อไม่ได้
- ยังไม่กันโกง: เบราว์เซอร์ของแต่ละคนมีสถานะเกมเต็ม (เปิด DevTools ดูมือเพื่อนได้) เหมาะกับ Open Test เล่นกับเพื่อน ถ้าจะทำแรงก์ต้องย้าย engine ไปรันบน server
- ถ้าข้อมูลการ์ดของสองเครื่องต่างกัน (card-api อัปเดตไม่พร้อมกัน) ระบบเทียบ hash แล้วไม่เริ่มเกม

## เด็คของฉัน
เก็บใน localStorage ของเบราว์เซอร์ (`af-mydecks`) ส่งต่อได้ด้วยปุ่ม "คัดลอกเป็นข้อความ" / "นำเข้าจากข้อความ"

## Deploy บน Render (Web Service)
1. push โฟลเดอร์นี้ขึ้น GitHub แล้วใช้ `render.yaml` ผ่าน Blueprint (หรือ New → Web Service: Runtime Node, Start command `node server.js`)
2. ADMIN_KEY ถูกสุ่มให้ ดูได้ที่ Dashboard → Environment แล้วเปิด `https://<ชื่อ>.onrender.com/recommece?key=<ค่านั้น>`
3. ถ้าเคยตั้งเป็น Static Site ไว้ ต้องสร้างเป็น Web Service ใหม่ (Static Site รันเซิร์ฟเวอร์ไม่ได้ ข้อเสนอแนะจะส่งไม่สำเร็จ)

## กฎการจัดเด็คตามธาตุ Avatar
- Avatar กำหนดธาตุของเด็ค ใส่ได้เฉพาะการ์ดธาตุนั้น (Avatar 2 สี เช่น BT01-001 ไฟ+มืด ใส่ได้ทั้งสองธาตุ) การ์ดที่ไม่ระบุธาตุใส่ได้ทุกเด็ค
- Unit ลงสนามต้องจ่าย Element ตรงสีของ Unit · Spell/Enchant/Equipment/Domain/Ultimate จ่ายตาม Cost ด้วย Element สีอะไรก็ได้ · ถ้าการ์ดไม่ระบุธาตุ จ่ายด้วยสีอะไรก็ได้
- หน้าสร้างเด็คจะทำการ์ดที่ธาตุไม่ตรงให้จางและเพิ่มไม่ได้ และ `AF.validateDeck` แจ้งข้อผิดพลาดถ้าเด็คที่นำเข้ามีการ์ดผิดธาตุ
- Element Deck เริ่มต้น 8 ใบ: Avatar 2 สีแบ่งครึ่ง 4/4
- ข้อมูลการ์ดหลายธาตุใช้ฟิลด์ `elements: ["ไฟ","มืด"]` (`element` = ธาตุแรกไว้แสดงไอคอน)
